# central-brain

## Tuning knobs / gotchas

- **`CHAT_DEEP_LINK_DELAY_MS` in `src/server/open/launch.ts` (currently 2000ms)** — the pause between opening a project window in VS Code and firing the `vscode://anthropic.claude-code/open?session=<id>` deep link that reopens a specific chat. If a cold VS Code start ever opens a *fresh* chat instead of the old one, the extension wasn't ready yet: bump this delay.
- **Never put anything volatile in the Codex hook command** (`src/server/hooks/codexHooks.ts`). Codex keys hook approval to the *exact* definition, so a path or a port in that string turns an app move, an upgrade, or a `CENTRAL_BRAIN_PORT` change into a dead pipeline that only a fresh interactive `/hooks` approval can revive. The command names one stable path — `<data dir>/hooks/notify-codex.sh` — and everything that varies (the endpoint, the install id) is read from `<data dir>/runtime/` at delivery time. See `docs/decisions/0004-codex-hook-reliability.md`.
- **"Codex hooks are working" needs three facts, not one.** The config must match the canonical definition, an event must be recent, AND that event must carry the current install id and a supported forwarder revision. `installed`/`trusted`/`live` used to be three booleans that could contradict each other; they are now one `diagnosis.overall` from `inspectCodexHooks()`. Add new causes there, not in the panel.
- Bumping `FORWARDER_REVISION` in **both** `hooks/notify-codex.sh` and `src/server/hooks/forwarder.ts` is required when the script's contract changes — and leave the old revision in `SUPPORTED_FORWARDER_REVISIONS` unless its deliveries genuinely differed, or every user pays a re-verification for nothing.
- The client is served from files enumerated at server boot (`@fastify/static` with `wildcard: false`) — after `vite build`, restart the server or new asset hashes 404 into the SPA fallback.
